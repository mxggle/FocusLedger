上一篇的结尾我写了一句话：「Yolo 终于不只是我自己能看的时间账本了，它开始能被 AI 读取了。」

这之后我又发了三个版本（0.2.0 → 0.3.0 → 0.4.0）。如果也要用一句话总结，那就是：让 AI 不只是能读，而是能动手；让一天结束以后，不只是被记录，而是能被看清。

记录是上一篇的事。这一篇是关于记录之后——专注的当下，和一天结束之后的复盘。

## 先让专注这件事，有了情绪

Yolo 的核心是一个很朴素的循环：开始一个任务，专注，停下来，留下记录。但 0.2.0 之前，这个循环是冷的。它工作，但它没有重量。

所以我先做的不是功能，是「情绪」。

- **承诺时刻（commit moment）**：开始一个新 session 的时候，焦点环会有一次光晕点亮和一句低语。注意是「新开始」才有——resume 和重新打开不算。因为承诺一件事和回到一件事，分量不一样。
- **完成的庆祝（celebration）**：只有在你真正点「Mark as done」时才会有那一下自信的爆发。它会尊重系统的「减少动态效果」设置。完成应该被看见，但不该廉价。
- **生命线（life thread）**：Today 页面顶部多了一行「第 N 周 / 约 M 周」。这不是装饰。它是想很轻地提醒你：你正在花的，是有限的东西。

同期还做了几件让循环更顺的事：把全屏的 **zen 模式**留给单个 session（Esc 或角落退出），把专注控制收敛成只有 **Pause + Done** 两个键（去掉了多余的 Stop 和「秒完成」的 Done——现在每一次完成都要走一遍 wrap-up，留下反思才算结束），加上桌面通知的权限流程，再补了一个 About 页面。

这一层我在设计文档里叫它「YOLO theme」。它只是薄薄地盖在专注循环上，但我想要的就是这个：工具可以是诚实的，也可以是有温度的，这两件事不冲突。

## 让 AI 不只是读，而是能动手

上一篇接的是只读的 MCP server——AI 能看见我的一天。0.3.0 我把它写穿了。

现在 agent 可以直接管理这一天：`add_task`、`update_task`、`start_task`、`pause_task`、`complete_task`、`drop_task`。关键不在于「能写」，而在于它写的方式和我自己在 app 里点是完全一样的：

- 所有写操作都走一个 `sessionService`，它镜像了 app 里 taskStore 的规则——同一时间只有一个 active session、切换任务时自动暂停、180 秒的续接窗口、太短的记录会被当作误触丢弃。
- 每一次写都包在一个 SQLite 事务里。
- 工具带上了 MCP 的标注（`readOnlyHint` / `destructiveHint` / `idempotentHint`），让调用方知道每个动作的性质。
- 想退回只读？`YOLO_MCP_READONLY=1`，写工具就不再注册，连接也以只读方式打开。
- server 永远不会去创建数据库（`fileMustExist` 是无条件的）——它是来读写你的一天的，不是来无中生有的。

还有一个很小但我很满意的细节：app 在窗口重新聚焦时会刷新。所以当 agent 在后台帮你改了任务，你切回来的时候，它就在那儿了。

这才是我说的「AI-native」真正落地的样子。不是在角落塞一个聊天框，而是 AI 能直接、安全地接手你这一天的运转。

## 顺手，让每一条记录都能被点开、被改

同一个版本里还做了一件小事：Today Log 里的每一条记录，现在都是一个可以点开的按钮。

点开是一个详情弹窗，能看到这段 session 的事实——时间、时长、完成度。如果是已完成的，还能编辑：任务名、分类、note、blocker、next action、完成度，全都能改。

我一直说 Yolo 记录的是「真实」。但真实不等于不能修正。你可以事后补一句当时没来得及写的 blocker，那它依然是真实的——只是更完整了。

## 一天结束，给我一份诚实的复盘

到 0.4.0，主线变成了一个问题：一天结束，我能不能不用自己重读一遍流水账，就看清今天到底发生了什么？

于是有了 **Daily Debrief**。它把今天的任务、session、还有那些停下来时随手写的 stop-note，揉成一段简短的反思。一天一份，存在新的 `daily_debriefs` 表里。

这是 Yolo 第一次真正用上 AI 生成，所以 AI 这一层我是认真搭的：

- **自带 key、多 provider**：Anthropic、OpenAI、Gemini，以及任何 OpenAI 兼容的端点。provider、API key、model、base URL 都在 Settings 里新开的 AI 区域配。
- AI 层本身是 provider 无关的（请求构造、响应解析、错误映射各自独立，带单元测试），请求统一走 `tauri-plugin-http`——这样桌面 webview 不会被各家的 CORS 策略挡掉。
- **输出语言可选**：20 种语言，默认 Auto（跟随你自己 note 的语言）。换语言时，只翻译分节标题，任务标题保持原样不动。

做完手动版本，我又把它推进了一步——因为「需要我自己想起来点一下」的复盘，多半不会发生。

所以 debrief 从一张内联卡片，变成了 Today Log 里一个小按钮、点开是个全局弹窗（从哪儿都能开）。再加上**定时自动复盘**：Settings 里一个开关加一个时间（HH:mm），一个 hook 每 30 秒检查一次，过了点就自动生成，一天最多一次，绝不覆盖你手动生成的那份，好了会弹一个带「View」的 toast，失败也只弹一次（不刷屏重试）。

调度那个判断「现在该不该跑」的纯函数（`shouldRunAutoDebrief`）是带单测的。这种东西一旦出错就是每天骚扰你，所以它值得被测。

## My Day：把一天摊开来看

复盘是一段文字。但有时候我想看的是结构。

所以 0.4.0 还加了一个 **My Day** 页面，这大概是这三个版本里我最喜欢的一屏：

- 顶部 hero 数据 + 日期切换；
- 一条当天的**时间线**，今天到底怎么流过去的；
- 一个分类**甜甜圈图**，时间都进了哪些桶；
- **估计 vs 实际**——我以为要花多久，和真的花了多久；
- 完整的 session 列表；
- 一段 AI 生成的叙事 **DayStory**，把这一天讲成一段话；
- 以及把整份日报导出成图片**分享**出去。

这一屏才是我说的「看清一天」。前面所有的记录、所有的诚实，最后都要落到这里：摊开来，一眼看见真相。（顺手还写了 seed 脚本和示例数据，这样空账户也能先看到这页长什么样。）

## 一些小事，但我在意

最后是一件不像功能的功能：macOS 的原生标题栏。

之前那条默认的不透明标题栏，和深色的 app 拼在一起，很出戏。0.4.0 我换成了 Tauri 的 Overlay 样式、隐藏标题，让深色界面直接延伸到标题栏底下。再铺一条贯穿顶部的拖拽区，把原生的红绿灯交通灯放进去，整个窗口都能拖。列分隔线起点压到拖拽区下面，这样侧栏收起时它不会去撞那三个灯。

为了让拖拽真的生效，还得单独授予 `core:window:allow-start-dragging`（它不在 `core:default` 里）。

这些没人会写进 release note，但它决定了一个东西「像不像一个原生 app」。我在意。

## 写在后面

把这三个版本连起来看，其实是一条线：

上一篇，AI 能读我的一天。这一篇，AI 能动我的一天，也能帮我回头看我的一天。中间我还顺手让专注这件事有了温度，让每条记录可以被修正，让标题栏像个正经桌面应用。

Yolo 的那句话一直没变：让你的时间，值得被看见。记录只是第一步，复盘才是它真正想换给你的东西——不是一张漂亮但自欺的完成清单，而是一份你敢直视的、关于今天的真相。

它现在还很早。但比起上一篇，它至少多会了两件事：动手，和回头看。
